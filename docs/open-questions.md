# Open questions

The module specifications raise these questions. A reviewer sorted them on 2026-11-16 into three groups. The proposed answers are recommendations, not decisions. Stage numbers in the answers refer to the first version of the plan; the stage table in [plan.md](plan.md) is current.

## For the project owner

These change what the application does or sounds like, or concern rights. Hanno Müller decides them before the stage of the module starts.

| Module | Question | Proposed answer |
|---|---|---|
| slicer, synth, metronome, console (stop silencing) | Fade length when onStop silences voices; should the Slicer use the user's Release time instead of 30 ms; synth Q5 asks for a value; metronome asks whether to add a short release ramp to avoid pops. | plan.md rule 8 requires 'Stop means silence' but the Sound decision says only defects that break behaviour are fixed. Recommend: one shared 30 ms linear fade for Slicer and Synth stops (new behaviour, inaudible as sound character, listed in CHANGELOG.md), and keep the Metronome's pops exactly as in the original (the Sound decision keeps Tom's sound), unless the owner calls the pops a defect. |
| beat | Global decay trim, D4 voice variants (bandpass snare, noise hi-hat) and D4's RND distribution are left out of Beat. (beat Q1, Q2, Q4) | This conflicts with plan.md Scope: 'The application must offer every function of the eight original files', and Beat is built from two files. Do not leave them silently out, because stage 3 is 'Done when every row of its parity table is ticked'. |
| beat | Filter MODE default OFF instead of D4's lowpass 4000 Hz. (beat Q3) | It changes what the user hears at first start. Recommend OFF (hi-hat stays audible, matches the BM source, the Sound decision keeps the sound of the primary RABBIT file); record the D4 difference in the parity table. |

| shell | Which of the three embedded logos is used? (shell Q2) | Rights are involved: plan.md Risks says the logo 'is used with Tom Tiest's permission'. Recommend: compare the three images by checksum; if identical use that one, if not use the newest file's logo, and record Tom Tiest's written permission for that specific image before stage 0 is merged. |
| shell | Default on/off state of each instrument at page load. (shell Q3) | It decides what the user hears at first start and the plan gives none. Recommend the spec's proposal (Beat on, Console on, the rest off), except consider Metronome off so a first Play is not a click only; the owner confirms. |

## Differences between specifications and plan that remain

A second review on 2026-11-16 found these after the specifications were aligned with the plan. The plan wins in each case. The person who builds the stage corrects the specification in the same pull request.

| Where | Problem |
|---|---|
| docs/modules/slicer.md, Transport behaviour, 'Tab hidden' bullet (line 109) | Says unmount() 'stops the waveform and VU loops'. The plan has one shared animation loop in audio/meters.js; ui/vu.js has no loop of its own and only deregisters from it on unmount. The waveform has no loop either (it is drawn on events). Replace with: unmount deregisters the VU from the shared loop and removes DOM listeners. |
| docs/modules/slicer.md, Tests, test_mount_unmount (line 194) | Test checks that 'unmount stops the VU loop'. Under the plan no instrument or ui/vu.js owns a loop, so the test should check that the VU deregisters from the loop in audio/meters.js. |
| docs/modules/slicer.md, Controls table (lines 46 and 51) and Tests test_ui_shared (line 196) | Uses ui/pad.js for the 'Clear sample' button and for the four filter-type 'segment pads'. Specify another component for these, or state that the pad is used in a different mode (this would also need a change in docs/plan.md, Shared building blocks). |
